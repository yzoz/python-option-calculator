## Технические требования по задачам

### T1. Валидация входных данных и типизация `dType` (🔴)
- В `bsm.py` ввести единый внутренний валидатор `_validate(S, K, V, T, dType)`:
  - `S > 0`, `K > 0` (иначе `ValueError` с именем параметра и значением);
  - `V ≥ 0`, `T ≥ 0` (иначе `ValueError`);
  - `dType ∈ {'C', 'P', 'F'}` (иначе `ValueError`).
- Обрабатывать `dType` согласованно **во всех** методах; убрать fallback‑ветки (`else: delta = 1`, `else` = put в `theo`).
- Явное поведение вырожденных случаев:
  - `T == 0`: `theo` = внутренняя стоимость (`max(S-K,0)` для call, `max(K-S,0)` для put), греки детерминированы (Delta = 0/1/−1, Vega/Theta/Gamma = 0);
  - `V == 0`: `theo` = внутренняя стоимость, греки = нули.
- Добавить type hints в сигнатуры (`float`, `Literal['C','P','F']`).

### T2. Безрисковая ставка `r` (🔴)
- Добавить `r: float = 0.0` во все методы `BSM` и в агрегаторы `Pricing`.
- Формулы:
  - `d1 = (ln(S/K) + (r + V²/2)·T) / (V·√T)`;
  - `theo_call = S·N(d1) − K·e^{−rT}·N(d2)`;
  - `theo_put = K·e^{−rT}·N(−d2) − S·N(−d1)`;
  - `theta` — с членом `r·K·e^{−rT}·N(d2)` (и put‑аналогом).
- Обратная совместимость: дефолт `r = 0.0` сохраняет прежние результаты.
- Задокументировать конвенцию и область применимости (BTC‑фьючерсные опционы, `r = 0`).

### T3. Иммутабельность входов и явный `exp` (🟠)
- **Запретить** запись в переданные словари (`param['exp'] = exp` удалить).
- Срок — явным параметром `exp: float | None = None`; проверять `exp is not None`, а не `if exp:`.
- Дефолты не должны изменять исходные объекты позиций.

### T4. DRY: единые агрегаторы и построение сетки (🟠)

- Переиспользовать во всех `*Full`‑методах, в `plot.py` и `searching.py`.
- Логику исключения `dType == 'F'` (Vega/Theta/Gamma) и спецслучая `F` (P/L) держать в одном месте.
- Заменить циклы `while` с ручным индексом на идиоматичные, где это не вредит читаемости.

### T5. Композиция вместо наследования (🟠)
- Слои:
  1. вычислительное ядро (`BSM`, портфельные расчёты) — **без** внешних зависимостей;

  3. поиск — зависит только от расчётов.

## Definition of Done

1. Все входные параметры валидируются; невалидные данные дают понятные исключения с контекстом (не `ZeroDivisionError`/голый `KeyError`).
2. Конвенция по `r` реализована и задокументирована; при `r = 0` сохранены прежние результаты (regression‑тесты).
3. Входные `params` **не мутируются** (есть тест); `exp = 0` обрабатывается корректно и явно.
4. Дублирование устранено; правка логики — в одном месте.
5. Архитектура слоистая через композицию; расчёты работают без `matplotlib`.
6. `searching` безопасен при импорте, возвращает результат, не печатает; сравнение float — с допуском.
7. Пакет устанавливается (`pip install .`), `matplotlib` — optional extra; импорт из любого каталога.
8. `pytest` проходит локально и в CI; покрыты parity, границы, отсутствие мутаций, smoke‑тесты.
9. README содержит установку/запуск/API/допущения; публичный API имеет docstrings и type hints.
10. Линтер (`ruff`/`black`) проходит без ошибок; код единообразен; `.gitignore` расширен.
11. Версия и CHANGELOG присутствуют; инструкция по релизу описана.
