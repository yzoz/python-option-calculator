### T1. Валидация входных данных и строгая типизация `dType` 🔴

**Что сделано**
- В `BSM` добавлены единые валидаторы:
  - `_check_numbers(S, K, V, T)` — `S > 0`, `K > 0`, `V ≥ 0`, `T ≥ 0`; при нарушении
    `ValueError` с именем параметра и значением.
  - `_check_type(dType)` — допускаются только `'C'`, `'P'`, `'F'`; иначе `ValueError`.
- Удалены «немые» fallback‑ветки: `else: delta = 1` в `delta` и неявная трактовка любого
  не‑`'C'` типа как put в `theo`.
- Задано явное поведение вырожденных случаев:
  - `T == 0` / `V == 0` → `theo` = дисконтированная внутренняя стоимость
    (`max(S − K·e^{−rT}, 0)` для call, `max(K·e^{−rT} − S, 0)` для put);
    `delta` = 0 / 1 / −1 по знаку «в деньгах», `vega`/`theta`/`gamma` = 0.
  - `theo` для `dType='F'` выбрасывает `ValueError` (линейный фьючерс не имеет премии).
- Добавлены type hints в сигнатуры (`float`, `Literal['C','P','F']`, `Tuple[float, float]`).
- Добавлен модульный docstring с конвенциями и описанием вырожденных случаев.

**Ключевое решение**
- Порядок проверок: сначала `_check_type`, затем короткое замыкание для `'F'`, и только потом
  `_check_numbers`. Это позволяет позициям `dType='F'` иметь `strike=0`, `vola=0` (у фьючерса
  их нет) без ложной ошибки валидации.

### T2. Явная обработка безрисковой ставки `r` 🔴

**Что сделано**
- Параметр `r: float = 0.0` добавлен во все методы `BSM` (`d1`, `d2`, `theo`, `delta`, `vega`,
  `theta`, `gamma`) и во все агрегаторы `Pricing` (`deltaFull`, `vegaFull`, `thetaFull`,
  `gammaFull`, `p_l`).
- Формулы обновлены под модель с дисконтированием:
  - `d1 = (ln(S/K) + (r + V²/2)·T) / (V·√T)`, `d2 = d1 − V·√T`;
  - `theo_call = S·N(d1) − K·e^{−rT}·N(d2)`, `theo_put = K·e^{−rT}·N(−d2) − S·N(−d1)`;
  - `theta` включает член ставки: call `− r·K·e^{−rT}·N(d2)`, put `+ r·K·e^{−rT}·N(−d2)`.
- Обратная совместимость сохранена: дефолт `r = 0.0` даёт прежние результаты.
- Конвенция и область применимости (BTC/фьючерсные опционы, `r = 0`) описаны в docstring.

### T13. Производительность (частично) 🟡

**Что сделано**
- `d1` и `d2` вычисляются один раз за вызов через приватный `_d1_d2` и переиспользуются во всех
  греках и в `theo` (устранён повторный `math.log`/`sqrt`/`erf`).
- `pdf` и `cdf` переведены в `@staticmethod`.
- Магические константы вынесены: `DAYS_PER_YEAR = 365`, `VEGA_SCALE = 100.0`.

**Осталось (перенесено в этапы C/D)**
- Переиспользование построенной сетки цен в `plot.py` и `searching.py`.

### Проверка

Команды и результаты:

- **Put‑call parity** при `r = 0`: `C − P = S − K` → ошибка `0.0`.
- **Put‑call parity** при `r = 0.05`: `C − P = S − K·e^{−rT}` → ошибка `0.0`.
- **Вырожденные случаи:**
  - `theo(100, 90, 0.2, T=0, 'C') = 10.0`, `'P' = 0.0`;
  - `theo(100, 90, V=0, 1, 'C') = 10.0`, `delta = 1.0`.
- **Валидация:** `S = -1` → `ValueError`; `dType='X'` → `ValueError`.
- **`example_greeks.py`:** Theo 10.37, Delta −0.07, Theta −40.61, Vega 1.0, Gamma 0.0.
- **Агрегаторы (`Pricing`)** на портфеле с `'F'`‑позицией (`strike=0`, `vola=0`) отрабатывают
  без ошибок; `delta('F') = 1.0`.

**Что сделано**

### T6 + T4. Обработка ошибок и дедупликация агрегаторов 🟠

**Что сделано**

- Логика «фьючерс не имеет vega/theta/gamma, но имеет delta=quant» инкапсулирована
  в `_option_greek` и в `deltaFull`/`thetaFull`.

- `plot.py` (наследник `Pricing`) продолжает работать: `plotPL` и `p_l` отрабатывают
